# tiny-vllm 영상 시나리오 — Prefill & Decode 중심 (재설계)

> 핵심 한 줄: **"당신이 질문을 입력하면, LLM 안에서 무슨 일이 벌어지는가."**
> 추상 개념 나열을 버리고, **구체적인 대화 예시 하나를 토큰 단위로 끝까지 추적**한다.
> 모든 내부 동작(임베딩·어텐션·FFN)은 "한 토큰의 여정"으로 prefill/decode 흐름 **안에서** 보여준다. 따로 떼지 않는다.

---

## 추적할 예시 (이걸로 처음부터 끝까지 간다)

**멀티턴 대화** — 대화가 누적되며 KV 캐시가 자라는 걸 보여주는 게 목적:

```
[1턴] 사용자:  대한민국 수도는?
      LLM:     서울입니다.

[2턴] 사용자:  거기 인구는?          ← "거기"가 서울인 걸 어떻게 아는가?
      LLM:     약 940만 명입니다.
```

2턴의 "거기"가 1턴의 "서울"을 가리킨다 — **이게 가능한 이유가 KV 캐시**다. 대화 전체가 캐시에 남아있기 때문. 이 한 가지를 깨닫게 하는 게 전체 영상의 목표.

## 구조: 3편 (각 3~5분)

| EP | 제목 | 한 문장 | 무엇을 깨닫는가 |
|---|---|---|---|
| **EP1** | 질문을 읽는 순간 — Prefill | 프롬프트 전체를 **한 번에** 처리해 첫 글자를 뱉기까지 | "입력을 이해하는 단계는 병렬이다. 그리고 K·V를 저장해둔다." |
| **EP2** | 한 글자씩 답하기 — Decode | 토큰을 **하나씩** 생성하며 매번 캐시된 과거를 본다 | "생성은 순차다. 매 글자마다 캐시에 한 칸씩 쌓인다." |
| **EP3** | 대화가 쌓인다 — KV 캐시와 vLLM | 2턴이 들어오면 캐시가 더 커지고, 결국 메모리가 문제가 된다 | "대화가 길수록 캐시가 커진다 → 이걸 관리하는 게 추론 엔진의 본질(vLLM)." |

내부 레이어 디테일(BF16, RoPE, GQA, tree reduction, 전치 트릭 등)은 **EP1의 '한 토큰이 레이어를 통과하는 줌인' 장면에서 빠르게 한 번** 훑고 지나간다. 별도 편으로 만들지 않는다. 더 깊게 보고 싶은 사람을 위한 건 `concept-inventory.md`에 남겨둔다.

## 핵심 비주얼: "대화 화면 + 엔진 내부" 동시 표시

화면을 **항상 두 층**으로 본다. 이게 이 영상의 정체성.

```
┌─────────────────────────────────────────────┐
│  [위층] 챗 UI — 사용자가 보는 것              │
│   사용자: 대한민국 수도는?                     │
│   LLM:    서울▌  ← 글자가 실시간으로 찍힘       │
├─────────────────────────────────────────────┤
│  [아래층] 엔진 내부 — 진짜 벌어지는 일          │
│   토큰들 · KV 캐시 막대 · 현재 처리 중인 토큰    │
└─────────────────────────────────────────────┘
```

위층의 글자 하나가 찍힐 때마다, 아래층에서 그걸 만든 연산이 동시에 움직인다. **"이 글자는 이 계산에서 나왔다"**를 1:1로 잇는 게 전부.

색(theme.ts): prefill=accent(#58a6ff 파랑), decode=accent2(#3fb950 초록), KV 캐시 K=파랑/V=초록, 새로 추가되는 캐시 칸=warn(#d29922 노랑 플래시), 경고/메모리 폭발=danger(#f85149).

## 제작 우선순위

1. **챗 UI 컴포넌트** (`<ChatPanel>`) — 위층, 타이핑 효과 + 글자별 reveal. EP1~3 전부 사용.
2. **KV 캐시 막대** (`<KVCache tokens step>`) — 아래층 주인공. append 성장이 핵심.
3. **토큰 블록 + thread 격자** — prefill(동시) vs decode(1개) 대비가 EP1·EP2 핵심.
4. **어텐션 부채살** — Q가 캐시를 보는 연결선. EP2·EP3.
5. **블록 분할/회수** (`<BlockTable>`) — EP3 후반 vLLM 파트.

## 정확성 가드 (ref/tiny-vllm 코드 기준)
- prefill: 프롬프트 모든 토큰 병렬 처리, 각 토큰 K·V를 캐시에 저장 (코드상 prefill 경로).
- decode: 토큰 1개만 처리, 캐시된 전체 K·V와 어텐션 (decode 경로, `dim3(num_active_slots, NUM_Q_HEADS)`).
- KV 캐시는 append-only, 시퀀스 길이만큼 선형 증가.
- 멀티턴: 새 토큰만 prefill해 기존 캐시에 이어붙임 (실제 서버 동작; tiny-vllm은 단일 시퀀스 데모지만 원리는 동일).
- PagedAttention: BLOCK_SIZE=16 토큰 단위, block_table 매핑, free_blocks 재활용.
- continuous batching: BATCH_SIZE=2 slot, is_slot_free/queue로 끝난 slot 재사용.
- **Llama 3.2 1B 전용**. 예시 토큰 분할("대한","민국"…)은 설명용 근사 — 실제 BPE 토큰 경계와 다를 수 있음을 자막 한 줄로 명시 권장.
